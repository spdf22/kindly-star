# 安全报告 / Security reporting

如果发现模板能诱导越权、伪造授权、隐藏指令或泄露私密信息，请提供去标识的最小复现。只含公开指令文本的问题可以提交 [Issue](https://github.com/spdf22/kindly-star/issues)。

**不要公开粘贴令牌、私密仓库内容、账号活动或未公开的对话。** 对包含这些信息的发现，先在 Issue 中仅说明“需要私下共享安全复现”，等维护者给出合适渠道后再共享。当前没有专用安全邮箱，也不承诺响应时限；不要把普通公开 Issue 当成私密渠道。

本项目提供文本指引，不能独立执行账户操作，也不能保证模型行为。发现宿主本身的权限问题时，应使用对应宿主的安全报告渠道。

## English

Report authorization confusion, hidden instructions, or privacy risks with a minimal de-identified reproduction. Public-text issues may be filed as a [GitHub issue](https://github.com/spdf22/kindly-star/issues).

Never paste secrets, private repository content, account activity, or unpublished conversations into a public issue. For sensitive findings, post only a request for a private reporting channel and wait for the maintainer to provide one. There is currently no dedicated security email or response-time commitment. A public issue is not confidential.

This instruction-only project cannot independently operate accounts or guarantee model behavior. Report host permission vulnerabilities to the host's own security channel.
