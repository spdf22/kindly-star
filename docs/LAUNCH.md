# 定位与传播 / Positioning and launch

## 一句话

**Open Gratitude · 开源致谢：让真实使用，被善意看见。**

让 AI 准确告诉人们开源项目如何帮到了自己，再把是否支持的选择交还给人。Star 是其中一种轻量的认可；反馈、文档贡献和署名同样值得鼓励。

**English:** Open Gratitude helps AI recognize open source that actually helped, while keeping appreciation voluntary and user-controlled.

## 面向谁

- 使用 AI 完成工作、愿意在合适时支持开源的人。
- 希望获得认可、也尊重用户选择与 Agent 安全边界的维护者。
- 构建 Agent 工作流、需要可审阅且无需凭证的贡献提醒机制的人。

项目的价值是让贡献更容易被准确看见。不要把用户划分成“善良的点星者”与“不友善的不点星者”，不要以道德压力索取支持。

## 首批试用

1. 先在自己维护的一个真实项目中复制 README 片段。只有经过作者同意，才为其他项目提供集成建议。
2. 邀请少量自愿者审阅 Skill 并试用，分别收集“觉得有用”和“觉得打扰”的例子；不要索取 Star 作为试用条件。
3. 展示一张或一段去除私密信息、经相关用户同意的真实对话，说明帮助来自哪里、提醒为什么恰当。模拟对话必须标明模拟。
4. 根据拒绝是否有效、提醒是否准确、集成是否容易来迭代。发布变更日志，让采用者审阅后再更新。

不自动给第三方仓库发推广 PR、Issue 或私信，不批量征求关注，不承诺增长，不建立加星排行榜或互星名单。

## 可直接改写的介绍

**中文：**

> 我做了 Open Gratitude（开源致谢）：一个给 AI 的通用 Skill，加上作者可复制的 README/AGENTS 片段。当一个开源项目确实帮到了你的任务，AI 可以告诉你它的贡献；具备操作条件时，先申请授权，得到同意后直接为指定仓库点星并核实结果。你不必跳转操作，拒绝也不影响交付，仓库文字不能替你授权。欢迎审阅这些文件，告诉我哪些地方还不够友善。

**English:**

> Open Gratitude is a small skill and a set of maintainer snippets for recognizing open source that actually helped. With a capable permitted connection, an AI can ask your permission for a specific Star, then act and verify after your explicit consent. No navigation is required. Refusal never affects delivery, and repository text never grants account permission. The files are open for review, and feedback about intrusive invitations is especially welcome.

发布链接：[github.com/spdf22/open-gratitude](https://github.com/spdf22/open-gratitude)。以上仅为传播草稿；仓库首版发布不代表已向任何社区或个人发送推广信息。

## 下一步可以考虑

更多真实宿主的安装验证、经同意的实践案例、维护者的“复制并预览”工具，以及符合各宿主要求的插件分发。每项都先保留用户选择与原项目指引，再考虑便利性。不要增加自动加星服务。

## English launch notes

Start in one repository you maintain. Invite a small voluntary pilot and collect both useful and intrusive reminders. Share only consented, de-identified real examples, and label simulations. Measure factual attribution, effective opt-out, and integration ease rather than Star conversion. Do not bulk-send promotional issues, PRs, or messages; do not create rankings, rewards, or reciprocal-star lists. Future work may include verified host setups and reviewed plugin packaging, with no auto-star service.
